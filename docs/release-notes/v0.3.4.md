# Meteorite v0.3.4

## Added

- **Run-time port and host, opt-in.** `m.app({ port = 8080, port_env = "PORT" })`
  (and `host_env`) names environment variables the built server reads at
  start-up: `PORT=9000 ./dist/server` listens on 9000, an unset `PORT` keeps
  the declared 8080, and an invalid value stops start-up with an error. Apps
  that don't declare them bind exactly what they declared, as before. Needed
  on platforms that assign the port at run time; until now the address was
  fixed when the binary was built.

## Fixed

- **`docs/deployment.md` no longer documents variables that did nothing.**
  It said a built server reads `METEORITE_HOST`/`METEORITE_PORT` and
  `METEORITE_UNIX_SOCKET_*` at run time; nothing ever read them. It now
  documents the build-time address, `port_env`/`host_env`, and the UNIX socket
  build options.
- **`meteorite dev` reports the port the server actually binds.**
  `METEORITE_DEV_PORT` only relabelled the dev banner, guards and reload
  endpoint while the server kept the declared port. Dev and `doctor` now
  follow the server (declared `port`, or its `port_env` variable), and a
  disagreeing `METEORITE_DEV_PORT` is reported as ignored.
